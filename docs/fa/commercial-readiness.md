# آمادگی تجاری و شروط انتشار.

کد قابل انتشار و برنامه قابل اجرای محلی است. این موضوع به معنی گواهی حقوقی، تأیید تولید، سازگاری همگانی یا مناسب بودن نگه‌داری اسناد واقعی مشتری بدون بررسی بیشتر نیست. مجوز نرم‌افزار اجازهٔ استفاده می‌دهد، نه گواهی انطباق یا ضمانت.

## پایهٔ پیاده‌سازی‌شده.

ورود UBL و CII، اصل رمز‌شده و بدون تغییر، پارس محدود، بخشی از کنترل منطقی، مرز اتصال اعتبارسنج رسمی، تاریخچهٔ بررسی، تأمین‌کننده و IBAN، بررسی و تأیید مستقل، سیاست نسخه‌دار، کنترل هم‌زمانی، تکرار و اصلاح، صف ماندگار، حسابداری آزمایشی و HTTPS عمومی، نقش، CSRF، کلید ورودی، شواهد، کنترل نگه‌داری، سه زبان و بررسی پشتیبان وجود دارند.

## پذیرش لازم پیش از بهره‌برداری تجاری.

1. KoSIT واقعی با نسخهٔ ثابت نصب و مجموعهٔ رسمی معتبر و نامعتبر اجرا شود. API فرزند، گزارش و پوشش مالیات و پروفایل ثبت شود. این محیط آن پذیرش را اجرا نکرده است.
2. ذخیره‌سازی با حجم و هدف بازیابی تطبیق داده شود. در صورت نامناسب بودن محدودیت تک‌گرهی، پایگاه تراکنشی و آرشیو تأییدشده جایگزین شود. بار، هم‌زمانی، بازیابی و ارتقا اندازه‌گیری شوند.
3. تست امنیت مستقل، CSP بومی، چرخهٔ کلید، MFA یا SSO مورد نیاز، بازبینی دسترسی و سخت‌سازی شبکه انجام شود.
4. متخصص حسابداری و حقوق آلمان مدت نگه‌داری، روش‌ها، مالیات، حذف، حریم خصوصی و استقرار واقعی را بررسی کند. گواهی GoBD، GDPR، EN 16931، XRechnung، ISO یا BSI ادعا نشده است.
5. قرارداد رسید و عدم تکرار هر مقصد حسابداری پذیرش شود. اتصال دارای گواهی DATEV یا SAP، Peppol، پرداخت، PDF ترکیبی، OCR و امضا موجود نیست.
6. ترجمه‌ها توسط متخصص بومی، دسترس‌پذیری با معیار منتخب، Windows و کانتینر و پشتیبانی و پاسخ رخداد بررسی شوند.

## نقشهٔ راه، نه قابلیت موجود.

قدم‌های بعدی PostgreSQL، هویت سازمانی و MFA، اتصال ممیزی به مرجع خارجی، پذیرش واقعی خودکار اعتبارسنج، PDF ترکیبی بررسی‌شده، رابط ERP، اعلان و اهداف عملیاتی قابل اندازه‌گیری هستند. استخراج AI یا اقدام مالی خودکار برای هسته لازم نیست.

عنوان درست انتشار «پیش‌نمایش مهندسی گردش صورتحساب Java با شواهد جداگانهٔ اعتبارسنجی و تأیید» است. عنوان «سامانهٔ کاملاً منطبق صورتحساب» بدون شواهد بیشتر درست نیست.
