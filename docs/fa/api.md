# قرارداد API و اتصال.

فایل OpenAPI 3.1.1 در `invoice-server/src/main/resources/openapi.json` است و پس از ورود از `/api/openapi.json` دریافت می‌شود. ۳۸ عملیات را توصیف می‌کند. مبالغ استخراج‌شده رشتهٔ اعشاری دقیق هستند؛ برای تصمیم حسابداری آن‌ها را به ممیز شناور دودویی تبدیل نکنید. خطا دارای `error.code` پایدار و شناسهٔ درخواست است.

## احراز هویت.

نشست مرورگر کوکی HttpOnly دارد. `POST /api/auth/login` مقادیر `tenant`، `login` و `password` می‌گیرد. پاسخ شامل `csrf` است و درخواست تغییردهندهٔ بعدی باید `X-CSRF-Token` بفرستد. تغییر از مبدأ خارجی رد می‌شود. کاربر جدید باید رمز اولیه را عوض کند. راز نشست نباید در localStorage ذخیره شود.

مدیر از بخش تیم و دسترسی کلید ورودی تاریخ‌دار می‌سازد. آن را به صورت `Authorization: Bearer <token>` بفرستید. کلید می‌تواند سند بفرستد و پروندهٔ متعلق به خودش را بخواند، اما بررسی، تأیید، خروجی، مدیریت کاربر یا خواندن پروندهٔ دیگران مجاز نیست. توکن فقط یک‌بار نشان داده و به‌صورت هش ذخیره می‌شود. برای واردکننده از این روش به‌جای رمز مدیر استفاده کنید.

## ورود سند.

```http
POST /api/invoices
Authorization: Bearer <intake-token>
Content-Type: application/xml
X-Filename: supplier-invoice.xml
Idempotency-Key: <submission-key>
```

بدنه باید XML خام باشد، نه multipart و نه پوشش JSON. سقف ۲ MiB است. همان کلید با بایت متفاوت خطای تعارض می‌دهد. اصلاحیه با `?supersedes=<case-id>` و سند جدیدِ تغییرناپذیر فرستاده می‌شود. در تلاش مجدد همان ارسال منطقی، کلید را ثابت نگه دارید.

## عملیات دارای نسخه.

`GET /api/invoices/{id}` نسخهٔ `version` را برمی‌گرداند. آن را همراه `review`، `approve`، `reject`، `comment`، `hold`، `revalidate` یا `export` بفرستید. بررسی به `costCenter`، `glAccount` و `note` نیز نیاز دارد. خروجی علاوه بر آن کلید عدم تکرار می‌خواهد. `GET .../report?attempt=0` نخستین اعتبارسنجی ثبت‌شده را می‌گیرد؛ بدون `attempt` گزارش آخر درخواست می‌شود. نبود گزارش خطای روشن می‌دهد، نه مدرک ساختگی.

## رابط حسابداری.

اپراتور یک مقصد ثابت HTTPS تنظیم می‌کند. JSON خروجی شامل هویت پرونده، مبلغ، کدگذاری، هش منبع و شواهد اعتبارسنجی است. کلید عدم تکرار ثابت می‌ماند. پاسخ موفق باید همان `invoiceId` و `receiptId` غیرخالی داشته باشد؛ کد ۲۰۰ به‌تنهایی کافی نیست. کار نمایشی هرگز URL خارجی را صدا نمی‌زند. اتصال دارای گواهی DATEV یا SAP، پرداخت خودکار، وب‌هوک ورودی و نقطهٔ Peppol در این نسخه پیاده نشده‌اند.
