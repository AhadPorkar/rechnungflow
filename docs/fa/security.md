# مدل امنیت و مرز تهدید.

صورتحساب، نام فایل، مقدار تأمین‌کننده و گزارش اعتبارسنج همگی نامطمئن هستند. DTD، موجودیت خارجی، طرح خارجی و XInclude غیرفعال‌اند و عمق، تعداد گره، ویژگی و حجم محدود می‌شود. استخراج مبتنی بر namespace به عنصر هم‌نام با فضای نام جعلی اعتماد نمی‌کند. رابط، محتوا را escape می‌کند و markup صورتحساب را اجرا نمی‌کند.

راز نشست تصادفی است و فقط هش آن ذخیره می‌شود. کوکی HttpOnly و SameSite است. عمر مطلق نشست هشت ساعت و زمان بی‌کاری سی دقیقه است. رمز با PBKDF2-HMAC-SHA256 و ۶۰۰هزار تکرار و salt مستقل ذخیره می‌شود. MFA، OIDC/SSO، بازنشانی ایمیلی و ارائه‌دهندهٔ هویت مرکزی وجود ندارد. پیاده‌سازی اختصاصی ورود نیازمند بازبینی مستقل است. محدودیت ورود محلیِ فرایند است؛ استقرار عمومی به محدودسازی مناسب در لبهٔ شبکه نیز نیاز دارد.

نقش و مالکیت مستأجر در سرور مستقل از پنهان بودن دکمه کنترل می‌شوند. CSRF و مبدأ مجاز از تغییرات نشست محافظت می‌کنند. کلید ورودی محدود، منقضی‌شونده و قابل لغو است و در فهرست به‌صورت واضح برنمی‌گردد. تغییر رمز یا دسترسی نشست را باطل می‌کند. آخرین مدیر از طریق API قابل حذف نیست.

اصل، گزارش و وضعیت با AES-256-GCM رمز می‌شوند و زمینهٔ مستأجر احراز اصالت می‌شود. کلید تولید را از داده و نسخهٔ پشتیبان جدا نگه دارید. رمزنگاری ذخیره‌سازی مانع خواندن داده توسط فرایند مجازِ نفوذشده نیست. چرخش آنلاین کلید پیاده نشده است.

CSP سخت‌گیرانه با هدر HTTP ارسال می‌شود؛ `unsafe-inline` یا `unsafe-eval` افزوده نشده است. آزمون مرورگر با واسط محلی، اجرای بومی CSP را اثبات نمی‌کند. آزمون بومی برای CI آماده شده است. XML به‌صورت پیوست دانلود می‌شود، نه محتوای اجرایی صفحه.

مقصد حسابداری ثابت و تحت تنظیم اپراتور است و HTTPS می‌خواهد. کنترل خروج شبکه، TLS، مدیریت راز، سیاست بدافزار، به‌روزرسانی میزبان، بررسی وابستگی‌های KoSIT و تست نفوذ مستقل همچنان لازم‌اند. زنجیرهٔ ممیزی محلی WORM یا متصل به مرجع خارجی نیست و تعویض کل داده و کلید را ناممکن نمی‌کند. انطباق خودکار GDPR یا GoBD ادعا نشده است.
